Case study, 002

Fixing UBA's OTP Login

A trust-first redesign of one of the more confusing entry points in Nigerian digital banking, built after a real login attempt went sideways.

TypeIndependent UX audit
FocusTrust, onboarding
ToolsFigma, HTML prototyping
01

A login screen that looks like a phishing page

It started with a simple task. Activate UBA SecurePass to authorize transactions from the mobile app. That required a User ID from UBA Internet Banking, a completely separate product from the mobile app already in use. The page that opened to provide it looked nothing like a bank.

02

Where the experience breaks down

Method: a heuristic evaluation against Nielsen's ten usability heuristics, plus a basic accessibility pass across Internet Banking, Mobile Banking, and SecurePass.

Critical

Fragmented app architecture

Internet Banking, Mobile Banking, and SecurePass are three separate downloads with three separate sign-in flows and no shared identity. A new user has no single banking home.

Major

Zero trust signals on the OTP login page

No HTTPS indicator, no current branding, no navigation. Visually close to indistinguishable from a phishing page mimicking the same layout.

Major

Circular SecurePass onboarding

SecurePass requires a User ID the user doesn't yet know they need, discovered only after the activation attempt has already failed.

Minor

Low feature discoverability

The Mobile Banking "Services" row clips horizontally with no visible scroll affordance, hiding features from new users.

Benchmark Nigerian fintech challengers like Kuda, Opay, and Moniepoint generally solve this with single-app onboarding and biometric-first login, with no separate token-generator app required for standard use. This isn't unique to UBA. Most legacy Nigerian bank apps carry the same layered-legacy-system problem, but it's exactly the gap that makes this an actionable, benchmarkable redesign rather than a subjective complaint.
03

Turning findings into fixes

Every change on the redesigned screen maps back to a specific audit finding. Nothing here was changed for looks alone.

No trust or security signal on the page → "Verified UBA Session" trust strip, always visible
User ID requested with no context → Inline helper text: where to find it in the mobile app
Competing OK / Cancel buttons → Single primary action, "Continue"
No phishing awareness built in → Footer security tip on what UBA will never ask for
Outdated visual identity, 2022 copyright → Refreshed type system, current-dated footer

04

Before & after

  • Trust signal visible before any input is given
  • Clear guidance on where to find the User ID
  • One primary action instead of two competing buttons
  • Built-in phishing-awareness messaging
05

What this changes

  • 01
    Lower hesitation at login.A visible trust signal directly targets the moment users second-guess whether the page is legitimate.
  • 02
    Fewer stalled sign-ups.Contextual helper text removes the most common blocker: not knowing where a User ID comes from.
  • 03
    Better phishing resilience.A page that visibly looks like the bank is one users can more confidently tell apart from one that doesn't.
These are directional, hypothesis-driven outcomes based on established usability heuristics, not measured results. This was an independent audit, not a commissioned engagement with UBA, so validating these effects would need real usability testing with UBA customers.
